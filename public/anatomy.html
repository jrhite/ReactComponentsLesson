Component tree

    Rules students take away

    Should this be a component?

    Extract it when you can say yes to at least one:

    1. It repeats. Avatar, Button, PostCard.
    2. It has one job you can name. If the name needs "and", split it.
    3. It owns state nobody else needs. SearchBar's keystrokes, UserMenu's open/closed.
    4. You'd change or test it on its own. PostCard with a fake post.
    5. The product has a word for it. "Profile card", "who to follow".

    Props or context?

    Use props whenUse context when
    The parent already has the dataMany distant components need it
    It's one or two levels downPassing it would cross layers that ignore it
    The component should show any item (Avatar, PostCard)It's app-wide: signed-in user, theme, language
    You want it easy to reuse and testIt changes rarely, so re-renders stay cheap

    Two smells to spot

    Too coarse

    • The same markup pasted in several places
    • A file over ~200 lines with several jobs
    • You can't test one piece without the whole page

    Too fine

    • A component that wraps one tag and passes one prop
    • Names like PostTitleWrapper or DivContainer
    • Opening five files to understand one card
