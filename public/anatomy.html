    Rules to take away

    Should this be a component?

    Make it one when at least one of these is true:

    1. It repeats. Avatar, Button, PostCard.
    2. It has one job you can name. If the name needs "and", split it.
    3. It owns state nobody else needs. UserMenu's open or closed.
    4. You'd test or change it on its own. PostCard with a fake post.

    Props or context?

    PropsContext
    Each child needs its own value, like each PostCard's postEveryone needs the same value, like the signed-in user
    The parent already has the dataMany distant components need it
    The component should show any item, like Avatar or PostCardIt's app-wide, like the signed-in user or the theme
    You want it easy to reuse and testPassing it would cross components that ignore it

    Too big or too small?

    Too coarse

    • The same markup pasted in several places
    • One file doing several jobs

    Too fine

    • A component that wraps one tag, like a PostTitle that is only an <h3>
    • Opening five files to understand one card

    That's why the menu items in UserMenu are plain <button> tags and not their own component.
